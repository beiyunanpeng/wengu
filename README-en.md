# wengu · 温故

> English translation of [README.md](./README.md) — the **Chinese version is authoritative**.

**A local-first mistake-review workbench for Chinese junior-high families (AI transcription as an optional add-on)** — no grading of real homework, no generated explanations, zero-model core: confirmed mistake intake → knowledge tagging → cross-subject spaced review → same-type quizzes → parent dashboard. Every family runs their own instance; data stays local by default (the optional external transcription step is documented in [`PRIVACY.md`](./PRIVACY.md)).

Not yet another photo-answer app — existing tools already do that well enough. **wengu builds the personalized mistake loop**: each family deploys their own instance, and data stays on your machine by default (the only exception: the external transcription you explicitly enable, see [`PRIVACY.md`](./PRIVACY.md)).

> Internal codename StudyDesk. **Split licensing: code MIT** ([`LICENSE`](./LICENSE)) + **data CC BY-NC 4.0** ([`LICENSE-data.md`](./LICENSE-data.md), **personal non-commercial use only**; the project as a whole is **not OSI-approved open source**). The knowledge-tree and question-bank seed data come from [`cn-math-taxonomy`](https://github.com/xiaoyang111222/cn-math-taxonomy) (author Aifeng); see [`THIRD-PARTY-NOTICES.md`](./THIRD-PARTY-NOTICES.md).

## ✨ Core loop

- 📥 **Grading happens outside the system** (the child marks and corrects on paper with a red pen; an external agent photographs the whole page → transcribes against a versioned template → watched import from `data/inbox/`)
- 📕 **Mistake intake** (a mistake enters the book only after human confirmation on the verification page; this is the only write path into the mistake table — no standalone manual-entry task)
- 🏷️ **Error-cause suggestion + child confirmation** (the external agent suggests; confirmed values and suggested values are stored with separate provenance; knowledge points = coarse pre-built seed + fine-grained controlled growth)
- 🔁 **Review scheduling** (fixed ladder + mastery-adaptive intervals + three anti-frustration rules; FSRS interface reserved)
- 📝 **Same-type quizzes** (auto-pushed when due, or parent-assembled papers; answer keys come from the question bank, **graded by code**)
- 📖 **On-paper correction replay** (the system generates no explanations and calls no models; for uncertain questions ask Doubao/a parent outside the system)
- 📅 **Priority daily queue + pomodoro** (auto-generated; timetable/calendar acts as a constraint layer)
- 👀 **Observation-and-review parent dashboard** (the child sees the same view; two roles + local PIN, not remote-control monitoring)
- 🔥 **Minimal check-in** (any question answered today lights it up — wrong answers count too; streaks are computed from facts, never stored; no points/badges)

## 🚫 Explicit non-goals (anti-over-engineering)

Olympiad-informatics judging infra · AI inventing math/physics/chemistry questions · speaking ASR · time-block auto-scheduling · real-time monitoring/screen lock · **public multi-tenant hosting with an account system** · cloud GPUs for models · microservices/Redis/external MQ/vector DB/K8s · Postgres by default · points and badges · agent frameworks such as LangGraph/CrewAI/AutoGen inside the product.

## 🛠 Tech stack

| Area | Choice |
|---|---|
| Backend | Python 3.11+ · FastAPI · async · modular monolith |
| Database | SQLite + WAL · SQLAlchemy 2 · Alembic migrations |
| Frontend | React 19 · Vite · TypeScript · Mantine · KaTeX |
| Core | **Zero-model**: the backend calls no cloud VLM/OCR/text model; no provider abstraction, no model-audit table |
| Grading | The system only grades its own same-type quizzes: runtime `judgeAnswer` normalized comparison; **`verify` runs in an AST-whitelist sandbox** (at bank-ingestion time) |
| Deployment | One-command Docker Compose; ports bind to loopback by default; remote access via **Tailscale (private tailnet)** |
| Distribution | Code under MIT + data under CC BY-NC 4.0; **every parent self-hosts their own instance** (single-user) |

## 🚀 Quick start (for parents who can install Docker but don't write code)

**Prerequisites**: Docker Desktop ([official site](https://www.docker.com/products/docker-desktop/)) + at least 2 GB of free memory.

```bash
git clone https://github.com/beiyunanpeng/wengu.git
cd wengu
cp wengu-api/.env.example wengu-api/.env   # optional; the v2.5 zero-model core usually needs no keys at all
docker compose up -d --build --wait
# Frontend: http://localhost:5173 (loopback-only by default; phone/tablet remote access: docs/deploy/mobile-access.md)
# Backend health check: http://localhost:8000/health
# Drop folder for external-agent transcription JSON: ./data/inbox (host side)
```

On first open you will see a **setup-wizard banner**: after the parent unlocks, you can review subject seed coverage and set daily review/recitation limits; the banner disappears once completed. The child area never asks for any personal information.

> To walk the whole path in order — "pick a deployment shape → start the services → back up first → connect a phone → record the first mistake" — with expected output at every step and bisection tips when something won't connect, see [`docs/deploy/from-zero.md`](./docs/deploy/from-zero.md)（从零开始 — from-zero guide; Chinese only）.

> If port `8000` is reserved by the system (common on Windows with Hyper-V), use instead:
> `WENGU_API_PORT=8100 docker compose up -d --build --wait` (PowerShell: `$env:WENGU_API_PORT=8100; docker compose up -d --build --wait`).

> **Loopback-only by default**: api/web are published to `127.0.0.1`; devices on the same network cannot reach them by default. Direct LAN access requires explicitly setting `WENGU_BIND_ADDR=0.0.0.0` (at your own risk — the child area has no login); for phones/tablets use Tailscale instead, see [`docs/deploy/mobile-access.md`](./docs/deploy/mobile-access.md)（手机/平板接入 — mobile access; Chinese only）. Do not rely on opening `0.0.0.0`.

> On networks in mainland China, configure registry mirrors in Docker Desktop → Settings → Docker Engine (e.g. `https://docker.m.daocloud.io`), otherwise pulling base images will be slow or fail. The API image build uses the Tsinghua pip mirror by default; override with `--build-arg PIP_INDEX_URL=...`.

> **Stop the API before inspecting the DB; use the built-in export for backups**: under Docker Desktop's shared mounts, reading/writing `data/wengu.db` from the host with SQLite while the container runs invalidates the container-side WAL/SHM and can lose writes not yet checkpointed (verified in practice). The parent-area "Backup" page export uses `VACUUM INTO` to produce a consistent snapshot and is **safe to run while the service is up**; a manual whole-directory copy of `data/` still requires `docker compose stop api` first; to inspect the DB while the container runs, use `docker exec wengu-api python -c "..."`.

### Local development (without Docker)

```bash
make install-api     # create wengu-api/venv (Python 3.12) and install dependencies
make upgrade         # create/upgrade SQLite to the latest migration
make dev-api         # http://localhost:8000/health
# in another terminal
make install-web     # npm ci
make dev-web         # http://localhost:5173
```

`make test` / `make lint` / `make migration-test` run the tests, ruff, and migration-rollback tests respectively.
On Windows, if `make` is not on PATH, reopen the terminal or install [GNU Make](https://winget.run/pkg/ezwinports/make) (`winget install ezwinports.make`).

> **`make dev-api` listens on `127.0.0.1` by default** (same policy as Docker): phones/tablets on the LAN cannot connect by default.
> For LAN debugging use `make dev-api HOST=0.0.0.0` — **this is a temporary debugging switch, not a remote-access solution**:
> the child area has no login, so exposing it to the LAN means no authentication; for remote access use Tailscale (see
> [`docs/deploy/mobile-access.md`](./docs/deploy/mobile-access.md)（手机/平板接入 — mobile access; Chinese only）). The port can still be overridden with `PORT=8100`.

## ⚠️ Security & compliance

- **Before any public exposure you must add authentication and user isolation**, or use **Tailscale (private tailnet)**; wengu is designed for "localhost / trusted LAN" by default.
  Cloudflare Tunnel / public reverse proxies are equally public exposure and are **not supported** — do not treat them as equivalent to Tailscale.
  Phone/tablet access steps: [`docs/deploy/mobile-access.md`](./docs/deploy/mobile-access.md)（手机/平板接入 — mobile access; Chinese only）; read-only self-check script:
  [`scripts/remote-check.ps1`](./scripts/remote-check.ps1).
- **The local parent PIN only prevents accidental entry, it is not a security boundary**: it guards only the "parent area" (voiding/paper assembly/bank review); the child area is PIN-free, and there is no login/account/multi-tenancy. Session cookies are signed with `WENGU_SESSION_SECRET`; when unset, one is generated on first start into `data/.session_secret` (multi-instance/public deployments must set it explicitly).
- Keys live only in `.env` (already gitignored); logs **never record full question text, answers, file URLs, or personal information**.
- Complies with the Personal Information Protection Law (《个人信息保护法》) and the Regulations on the Protection of Minors in Cyberspace (《未成年人网络保护条例》) — learning data stays on your machine by default; **the only step that ever leaves the machine is the optional external transcription**
  (PII-erased, cropped page images sent to a domestic third-party AI, requiring separate guardian consent); the field list and erasure guide are in [`PRIVACY.md`](./PRIVACY.md)（隐私声明 — privacy statement; Chinese only）;
  if that is unacceptable, use the offline `/import` manual-entry path — the core loop stays fully intact.
- The knowledge-tree and question-bank seed data (if you enable `seeds/`) is **personal non-commercial use only**, see [`LICENSE-data.md`](./LICENSE-data.md) and `THIRD-PARTY-NOTICES.md`.
