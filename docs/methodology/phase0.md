# Phase 0 = 手写识别 + 分题型判分实测 → 产出《自动入库边界表》

> **硬约束**（AGENTS §2.1）：**Phase 0 边界表未回填前，禁止实现"错题自动入库"和"自动排复习"**；未覆盖题型一律走保守档（待确认/讲解）。

## 为什么要有 Phase 0

多模态大模型判手写作业**不是全知的**——用户日常经验（豆包爱学等）与本项目实测都证明：**模型"把题讲对"比"把你的手写答卷判对"靠谱得多**。判分栽在 OCR 与过程容错上，讲解靠模型本身解题。所以：**"错题自动入库"的边界必须先实测出来**，而不是"信了模型再说"。

## 实测协议

### 1. 备样本
用**孩子真实作业照片**（不是网图），每类题型尽量 ≥15–30 题、多页多光线：

- **数学**：口算/计算 · 选择 · 填空 · 解答（多步）· 几何
- **物理**：选择 · 填空 · 计算大题
- **化学**：选择 · 方程式配平书写
- **英语**：单词/短语默写 · 语法选择
- **语文**：字音字形 · 病句选择 · 古诗文默写 · 阅读理解
- **脏样本**（重点）：混科目 · 潦草 · 涂改 · 双页平铺 · 反光 · 密集

### 2. 备真值
家长/孩子人工标出每题的**题目原文 + 孩子实际作答 + 该题对错**——这是对照基准。手写太乱时人工誊一遍即可。

### 3. 逐题填表
每家供应商 × 每题一行；关键字段（本仓库推荐的 schema）：

```csv
sample_id, date, subject, qtype, section, legibility, source_type,
provider, model_tier, is_objective,
q_ocr_ok, ans_ocr_ok, grade_ok, grade_err,
explain_score, explain_leaks_answer,
cost_cny, latency_s, note
```

字段含义：
- `is_objective` = 1 客观可判对错 / 0 本质无对错（阅读/作文等），后者不参与判分统计
- `q_ocr_ok` / `ans_ocr_ok`：识别的题目 / 孩子作答是否与真值一致（1/0）
- `grade_ok`：判分结果是否与真值一致
- `grade_err`：**漏判错**（错的判成对，最危险）/ **误判错**（对的判成错）/ 0（无）
- `explain_score`：讲解质量 1–5；`explain_leaks_answer`：讲解是否直接甩答案
- `cost_cny` / `latency_s`：单次调用成本 / 延迟，用于校准 §7 账单护栏

### 4. 聚合与判档

**判据核心看两个数**：`ans_ocr_ok` 通过率（防污染错题本）与 `漏判错率`（把错判成对、毁调度）。

按 `题型 × 供应商` 分组后套用阈值：
- **高置信自动**：题目识别 ≥0.95 且 作答识别 ≥0.95 且 判分 ≥0.90 且 漏判错率 ≤0.05 → 允许自动入库 + 排复习
- **中置信待确认**：识别稳定（≥0.90）但判分或漏判未达自动线 → AI 初判落"待确认"、孩子核对转正
- **低置信/讲解**：识别任一 <0.90，或 `is_objective` 全 0 → 走人工/讲解，不进错题流

## 本项目首轮实测结论（2026-10-21）

**9 题 × 5 档（豆包 lite/pro/turbo + Qwen flash/max）= 45 次调用**，v2.4 已吸收进设计文档 §13：

- **15 个 题型×供应商 组合全部落在"低置信/讲解"**——不是判分能力问题，是**题目识别准确率 0.0–0.5 拖垮一切**。
- **边界表本轮不能回填**，**Phase 1 全量按"待确认"保守起步**。
- **按题型路由供应商是必需项**：物理豆包占优、字形默写 Qwen 占优。
- **档位越高 ≠ 判得越好**：turbo 更贵更慢更差。
- **误判错四根因**：纯判分错 / 提取错级联到判分 / `〔?〕` 占位工作正常 / 模型方差。
- 成本约 **14 元/月**（按 750 题估），远在 200 预算内。

## 下一轮回填边界表的前置

1. 补"孩子做错"样本 ≥5 题测漏判错率（首轮只有 1 道做错，样本不足）
2. 每题型样本扩到 ≥20
3. **识别链路优化**（v2.4 借鉴 KuroTutor）：**先本地 OCR 行聚类切题 → 再喂 VLM 精读**；qwen3.5-ocr 车道、豆包 `thinking.type=disabled` 提速
4. 复核其余 8 题真值清单
