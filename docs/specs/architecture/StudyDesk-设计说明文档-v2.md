## 一句话定位
不是"再做一个拍照答疑 App"，而是把 **错题自动归集 → 错因/知识点分类 → 跨科复习调度 → 每日任务 → 家长复盘** 这条个性化闭环做出来并**做得可信、可维护、可分发**。

---

## 1. 产品定性与边界
- **形态**：半自建（AI + 本地脚本 + 云模型 API）。**开源分发**：每个家长**自托管自己的一份**——**多实例、各自单用户**，**不做 Hosting 多租户、不做公网账号体系、不商业化**。
- **覆盖科目**：数学、英语、语文、物理、化学 + 信息学竞赛（C++）。
- **北极星指标**：**每周有效复习题数**（不是使用时长、不是打卡数）。
- **最终目的**：帮孩子建立**自我管理能力**，家长做**观察复盘**而非遥控监控。

## 2. 全局架构
- **应用**：单一 **自托管 Web 应用（Web + PWA）**，手机/PC 浏览器同开，PC 为宿主。
- **后端**：**Python + FastAPI + async**；**模块化单体**，不用自主 Agent 循环、不用微服务。
- **数据库**：**SQLite + WAL**（foreign_keys、busy_timeout），**SQLAlchemy + Alembic** 迁移；**只跑一个可写实例**。上云或换 Postgres 是"将来按需"，非默认。
- **存储**：**本地磁盘目录**（`./data/uploads/`）为默认；**MinIO/S3 为可选插件**（高级用户/真上云）。
- **前端**：**React + Vite + TypeScript + Mantine + KaTeX**（数学渲染刚需）+ PWA；信奥代码编辑内置 **Monaco**。
- **任务队列**：**不用 Redis/外部 MQ**；用 `ai_jobs` 表 + 进程内并发 1–2 的循环（幂等领取、超时回置、失败重试一次）。
- **模型层**：见 §3。
- **部署**：**Docker Compose** 一条命令起全栈；远程访问先 **Tailscale/Cloudflare Tunnel**，预留将来原样上云（搬 SQLite 文件 + 挂载卷）。
- **数据留家**：原图、题库、错题、看板、日志全在本地卷；云推理必要地上图（题目不含个人信息，家长已接受）。

## 3. 模型调用层（可插拔 + 成本护栏）
- **至少两家云供应商、可配置互备**：主 **火山引擎豆包（教育版多模态，与豆包爱学同源）**，对照 **阿里百炼 Qwen-VL**，候选 **腾讯云教育智能批改**；文本侧支持 DeepSeek/GLM/Kimi 等 OpenAI-compat。
- **`VisionProvider` 适配层**：统一 `extract_problem()/grade()/solve_explain()`；按 `protocol`（OpenAI-compat / Anthropic-compat）分发 HTTP 客户端；**加一家 = 一个 adapter + 配置，不改业务**；**提供 mock provider** 供测试。
- **禁止**把某家 SDK 渗进业务逻辑深处。**按题型路由供应商 = 必需项非可选**（路由表来自 §13 Phase 0 结论：物理豆包占优、字形默写 Qwen 占优）。**"档位越高 ≠ 判得越好"**（实测 turbo 反而比 lite 差、成本 5×、延迟 4×）——**选型按题型实测，不按价格档直觉**。
- **成本护栏（必配）**：日常走性价比档、难题升旗舰档、变式/加练按需触发；**每日批量调用上限**；**内容哈希三级缓存 + `ai-raw/` 原始响应落盘**（缓存键 = 内容哈希@模型@prompt版本）；应用内 **`model_runs` 自计**月度用量/成本；README 强制"云控制台设账单上限+告警"。

## 4. AI 可信工程纪律（v2 新增的核心层）
> 这是"把不确定的模型输出，跑成可信系统"的地基，来自参考项目的实战沉淀，优先级等同功能。

- **事实源 + 幂等 + 确定性重算**：`learning_events` 为 **append-only 事实源**（UNIQUE 防重复计数）；掌握度、复习排期、毕业状态一律**由事实确定性推导、可整体重算、不存易变字段**（毕业=尾部连对≥3 的推导，非存储）。AI 任务记 `to_event_id` 水位，运行期新增数据留下一次，不扩大当前任务。
- **宽松解析层 vs Schema 校验层 分离**：先尽力从模型 JSON 抖动里"救"出结构，再用 Zod/Pydantic **严格 Schema 校验**；所有模型输出必经校验。
- **AI 建议值 与 用户确认值 分离存储**：字段带来源标记（`vlm/ai/student/parent`）+ 置信度 + 版本；**确认值优先进入后续上下文**，旧版保留不静默覆盖。
- **提示词版本化真源**：全部 prompt 以 `llm_prompts/*.md` 为唯一真源，frontmatter `id`+`version`，启动加载、语义变更**必须递增版本号**；每次运行记 `prompt_version`；豆包侧模板只是"部署副本"，改词先改仓库文件。
- **导入即不可信输入**：豆包 JSON / 照片识别结果都按不可信处理——校验大小/题数/字段长度、**提示注入防御**（题目文字只作被分析内容，绝不改系统规则或触发工具）、**识别不清用 `〔?〕` 占位不猜**、模型不执行代码/不开链接/不产未处理 HTML。
- **提取质量前置闸门（v2.1 一等公民）**：题目残缺、含 `〔?〕`、作答为空 → **直接路由人工复核，绝不进判分链路**。Phase 0 第②类误判（提取错→判分错）证明此闸门缺失代价巨大。
- **模型只提、代码才判（v2.1）**：**客观题判分禁止让模型推理**——模型负责提取孩子作答，判分交给**确定性代码做归一化字符串/集合比对**（含 `acceptableAnswers` 别名）。Phase 0 第①类误判（提取全对模型仍判错）证明"让模型看题+作答→判对错"这条裸链路不可靠。
- **审计与隐私**：`model_runs` 记 任务类型/供应商/模型/prompt版本/耗时/用量/状态，但**绝不记题目全文、答案、文件 URL、个人信息、密钥**；密钥只走环境变量。
- **反虚假精确**：样本 < 3 不下结论；价值不确定的功能**做成默认关的开关**（如"概念重逢复活")。

## 5. 各引擎边界（实现规格）

### 5.1 采集与识别（双通道 + OCR 预处理，v2.1 修订、v2.4 加预处理）
> **【v2.5 取代】** 本节"手机拍照→VLM 主链路 + 本地 OCR 行聚类切题 + 整页直读"整套**已作废**，改由**外部 agent 整页拍→按 `docs/templates/doubao_transcribe_v1.md` 转录已批改错题→监听目录导入→核对页确认**；wengu 系统内不再做任何视觉提取/切片。以 **§16.A** 为准，下文仅存"回显总闸 + `〔?〕` 占位 + 导入即不可信输入 + 提取质量前置闸门"这些仍有效的确定性纪律。

- **主通道（方案 A）**：手机（安卓/iPad）拍照 → **HTTP 接收端秒传** → 落对象存储 → 建 `photo_capture` → 触发处理。iPad 作看结果终端；网盘仅批量兜底。
- **OCR 行聚类切题预处理（v2.4 新增，KuroTutor `services/layout.py` 借鉴）**：整页照片先经**本地 OCR（PaddleOCR / RapidOCR，不联网、不调 VLM）检测文本行 → 按题号锚点 + 垂直间隙聚类 → 裁切成单题子图**，再喂 VLM 精读。**Phase 0 已证明整页 VLM 直读的题目识别准确率 0–0.5 是主瓶颈；先切题再精读能显著提升准确率并降 VLM 成本**——对**双页平铺**尤其关键（Phase 0 §13-E 项发现的共同弱项）。
- **兜底通道**：**豆包 JSON 导入**——人工把作业交给豆包按版本化模板产出 JSON 数组导入，用于**补录历史卷 / 识别失败**。导入**不调模型**，只确定性校验+归一+生成可编辑草稿。
- 两条通道**共用同一套草稿结构与确认流**。
- **回显总闸（必须）**：任何结果页同时显示"系统识别到的题目 + 孩子的作答"，一眼纠错。**纯查询页面绝不触发模型调用**（只读已有数据/任务状态）。
- **提取质量前置闸门（一等公民）**：题目残缺、含 `〔?〕`、作答为空 → **不进判分链路，直接路由人工**。Phase 0 数据说明：题目识别准确率（普遍 0–0.5）是**当前主要瓶颈**，必须先切题预处理 + 做扎实识别再谈下游。

### 5.2 批改（判作答）与答疑（解题）——两个引擎（v2.1 大改）
> **【v2.5 取代】** 本节"对真实作业/考试题做批改分级 + 模型答疑"的整套**移出系统**：真实题的**批改/引导/解析都在卷子上外部完成**，wengu 只把**已确认的错题**转录入库、**不再判真实题**。wengu 内**唯一保留的判分场景**是"系统自造同类题考核"——答案钥匙来自 seed 题库（已知 `answer`/`verify`），走确定性 `judgeAnswer`（运行时）+ AST 沙箱 `verify`（入库核验）。以 **§16.B / §16.D** 为准。"模型只提、代码才判"这条纪律**不废弃**，只是作用域从"判真实作业"收缩为"判系统自造题"。

- **答疑**：单题"我不会" → 模型解题 + 三段式讲解；强项、可全自动；复用讲解引擎，**不单独重造**。
- **批改 = 分级闸**（档位来自 §13 边界表；**本轮未回填 = 全走"待确认"保守起步**）：
  - **客观题**（口算/选择/唯一填空/单词·古诗文默写）→ **模型只提取作答，判分交给确定性代码做归一化字符串/集合比对**（含 `acceptableAnswers` 别名）；比对成功 → 自动入本 + 排复习；比对失败/含 `〔?〕` → 转"待确认"。**严禁让模型对客观题二次推理判分**（Phase 0 第①类误判已证不可靠）。
  - **过程题**（数理大解/化学方程式）→ 模型给"逐步比对 + 偏保守初判"，**默认落"待确认"**，孩子核对才转正；判分波动大（Phase 0 第④类）时可**多次采样一致性检查**。
  - **开放题**（阅读/作文/多解）→ 走讲解，不进错题流。
  - 允许"申诉/标记判错"，改判不重复计入掌握度。
- **`【依赖图形】` 边界**：几何/物理等"依赖图且导入不带图"的题，用**确定性关键词规则**（题干"如图"等指涉或标记）识别，**不参与自动判分与复习**，只保留统计与归因。
- **"只判对错"模式（v2.4 通用护栏）**：批改引擎可配置为**只输出正误、绝不显示标准答案/解析/范文**——防止"AI 批改=一支更漂亮的红笔"（孩子照抄答案伪闭环）。这是平台级一等公民配置（非某科特化），与"要答案须先动手+留痕"（§5.5）配合使用。

### 5.3 错题本（心脏）
- **入本 = 批改判错的自动副产品**，不设独立录入任务；**错题表有唯一写入路径**——**变式题绝不进错题本**。变式/加练的作答记录改走 **`practice_records` 派生表**（v2.4，KuroTutor quiz / wrong-notebook `PracticeRecord` 印证）：保留"练过哪些变式、对错如何"的可回看能力，但**不进错题、不参与复习排期、不影响掌握度**（可整表清空）。
- 字段：题目原文/图、标准答案、孩子作答、正误、错因(候选)、知识点、来源、置信档、状态(待确认/已入本)、复习调度、订正、申诉、**`mistake_versions` 内容版本（只追加不 UPDATE）**。
- **错因**：AI 预填候选 + 孩子一键确认/纠正/补一句；画像级学习方法结论（审题/计算/检查习惯/紧张…）带证据+置信度、可被孩子纠正、不静默覆盖。
- **前置知识回溯诊断（v2.2 新增、v2.3 细化）**：错因归类含 **"前置知识缺失"** 一档；错题挂载知识点后，系统沿 `dependencies.json` 的先修边（hard/soft）**向上回溯**，找**最近一个未掌握的父节点**，**优先排入复习队列**——先补前置、再练本题。具体算法（Python 重写 ~200 行、参考 `cn-math-taxonomy` `diagnose/engine.js`）：
  - **每知识点最多 2 题**：第 1 对 → mastered（全部祖先推断掌握）；第 1 错 → 补第 2；第 2 错 → **weak**、把未判定的直接先修（**hard 先 soft 后**）压栈顶深度优先回溯；第 2 对 → **shaky**、不回溯。
  - **停止条件**：题量上限（默认 16、筛查 40）或栈空。**根因 = weak 且其先修中无 weak**（未测先修要标"真正根因可能更靠前"）。
  - **可确定性重放**：选题用固定种子（如 `mulberry32`），同 `answers` 输入可 `replay()` 完整重建——与 §4 `learning_events` 事实源纪律同构，便于回归与申诉。
  - **难点在判题规范化不在图算法**：`judgeAnswer` 必须做 NFKC 全/半角、多答案按 `,、；和/或` 拆分、`1/2 ≡ 0.5 ≡ 50%` 有理数精确比较、坐标、单位别名、带分数（README 有完整规则清单）。数据源与算法参考 §14。
- **知识点标签：两级混合（v2 修订）**——
  - **粗粒度 `category`：预置"初中学科标准知识点树" seed（可换教材包）**，稳定，作为跨科统计与组卷的锚点；
  - **细粒度 `concept`：允许从错题受控生长**，但守防碎片化三道防线：优先复用已有分类、模型不覆盖用户确认值、归并需人工确认（带 `concept_aliases`）。

### 5.4 复习调度（v2 修订：固定阶梯优先；v2.4 加掌握度自适应间隔因子）
- **MVP = 固定间隔阶梯 + 掌握度自适应因子 + 三段抗挫败规则**，**不用 FSRS**：基础档数学 1/10/30、记忆科 1/3/7/14/30（`review_intervals` 可配）；**实际间隔 = 基础档 × (1 + mastery × 4)**（KuroTutor `review.py` 公式），`times_wrong > 1` 时**折半**、**答对减一、归零 = 毕业**。
- **mastery 定义（v2.4 定案）**：某 concept 的 mastery = 该 concept 下历史作答的正确率（当前 `recompute.mastery()` 为简单比例，可后续升级为近期加权）；**一道错题挂多 concept 时，排期取所有已确认 concept 中最小的 mastery**（保守，不放过薄弱点，与"抗挫败 + 前置回溯"哲学一致）；无 concept 挂载时 mastery=0.0。
- **抗挫败三规则**：**答错不倒退**（原地）、**下次从实际完成日起算**（逾期不丢题不惩罚）、**尾部连续对 ≥3 才毕业**。
- **两段式**：先重做原题（对→按需变式确认迁移，错→回讲解重排）；变式/加练 = **检索真题组卷、绝不 LLM 现编**，异步、高置信才出，作答记 `practice_records`（§5.3）。
- **算法可插拔**：复习引擎做成接口，**FSRS 作为将来数据量够时的升级路径**（用客观对错喂 good/again）。
- **掌握度信号四档**：能客观批改用客观 → 不能退自评 → 都没有**只做待办不排复习**，绝不硬塞假信号。

### 5.5 三段式讲解
- **定位 →（引导 / 讲解）→ 巩固**；默认模式按错因预选；引导最多 3 级递进提示、不直接甩答案。
- 孩子随时可"看完整讲解"，但须先在引导里动手一次；**"直接要答案"留痕进看板当趋势、不硬拦**。
- 讲解**语气温暖、答错共情**（陪伴感 ≠ 积分；不上游戏化）。数理化用引导阶梯；背诵类退化为"给语境 + 复述"。
- **讲解可锁"无范文"档（v2.4 通用护栏）**：家长配置里可把讲解引擎设为**只诊断、不给范文/好词好句**（英语写作尤其重要）；并支持**"无反馈自测"模式**（只写一遍、不给 AI 看、按自查表打勾），用于验证能力是不是长在 AI 身上。

### 5.6 规划引擎
- **优先级日队列 + 番茄钟执行**（番茄钟是计时器，不是规划器）。
- 日队列**自动生成**：到期复习 + 固定背诵打卡铺底 → 提取的作业按 deadline 插入 → 硬事件（月考/信奥课）自动抬权重。
- **课表/日历 = 约束层**，不做时间块排课日程。孩子只做"清队列 + 偶尔延后/划掉"。

### 5.7 长期计划
- **覆盖型**（期中复习、信奥学新）：圈知识点树范围 + deadline，按**掌握度自适应**动态挑"下一个最该学点"喂日队列（非死倒排）。
- **积累型**（每日背诵/单词）：streak。
- 目标由**家长与 AI 共创、图谱优先 AI 生成后家长审核**；孩子只执行。

### 5.8 信奥（独立流）
- 平时练习在**洛谷/一本通**，判题在外部。**工作台不建判题 infra**。
- 只承接：卡壳题（截图题目+代码，复用采集）→ 三段式引导 → **记入"待重做清单"**。
- **不自动排复习**；需要额外练时**手动组卷**（C++ 题库检索）。用独立 C++ 技能图谱（语法→算法→数据结构→专题，对齐 CSP-J/S）。

### 5.9 英语 / 语文（尽量复用既有引擎）
| 项 | 信号档 | 复用引擎 | 进复习队列 |
|---|---|---|---|
| 口头背诵 | ③自评 | 内建自评间隔重复 | 进（自评驱动） |
| 默写·听写 | ①客观 | 拍照批改 | 进（客观驱动） |
| 听力 | ①客观(需音频+题) | 组卷+批改（教材音频+TTS） | 进（依赖音频来源） |
| 字音/病句/文言选择 | ①客观 | 批改+组卷 | 进 |
| 作文/阅读理解 | 无客观对错 | 讲解+AI给分/范文对照 | **不进**，留成长记录 |
| 口语跟读评测 | 需ASR | —— | **不做** |

### 5.10 家长看板与角色（观察复盘型）
- 看趋势：完成度、番茄时长、错题存量、**知识点薄弱热力图**、掌握度曲线、复习积压、"要答案"次数、申诉数、信奥待重做进度。**孩子见同一份**（透明，数据不武器化）。
- 家长=观察 + 少量配置（长期目标、组卷、审核题库、偶尔补推任务），**不实时催/不锁屏/不逐项问责**。
- **角色**：孩子默认视图 + **家长本地 PIN** 解锁家长视图。**免登录仅限本机/可信内网**；开源场景见 §6。
- 打卡极简（streak + 掌握度曲线）；提醒 MVP 只做"打开弹窗"，家长推送仅"低频周报"。

### 5.11 输出（家长刚需）
- **错题 PDF 四区块导出打印**：原题 + 孩子作答 + 解析 + 批注（参考项目验证的家长痛点）。支持按章节/知识点聚合组卷导出。

## 13. v2.1 修订记录（2026-10-24，吸收 Phase 0 首轮实测）

Phase 0 首轮已跑（9 题 × 5 档 = 豆包 lite/pro/turbo + Qwen flash/max，45 次调用；见 `Phase0-实测/判分五档对比-2026-10-21.md`、`判分初测小结-2026-10-21.md`、`边界表_单题判分.csv`、`边界表_页级识别.csv`）。核心结论与由此驱动的设计修订：

**A. 边界表本轮不能回填**
- 15 个 题型×供应商 组合**全部落在"低置信/讲解"**——不是判分能力问题，是**题目识别准确率 0.0–0.5 拖垮一切**（阈值 0.90 远未达）。
- **Phase 1 全量按"待确认"保守起步**（规矩：未测到 = 保守档）；下一轮识别链路优化（`qwen3.5-ocr` 车道、豆包 `thinking.type=disabled`）+ 每题型样本扩到 ≥20 + 补做错样本 ≥5 测漏判错率 → 回填并逐步放开。

**B. 按题型路由供应商 = 必需项非可选**（→ 修订 §3、§5.2）
- 物理 phy29：豆包 3 档全对、Qwen 2 档全错 → **物理走豆包**
- 字形默写 chi_zi2：豆包 3 档全错、Qwen 2 档全对 → **字形走 Qwen**
- 路由表进 P1-2 Provider 层的配置（不是硬编码分支）。

**C. 档位越高 ≠ 判得越好**（→ 修订 §3 成本护栏）
- 判分正确数 `lite(8) = max(8) > pro(7) > turbo(6) = flash(6)`；turbo 更贵（0.037 元）更慢（295 s）更差，中间档无选型价值。
- **选型按题型实测，不按价格档直觉**；成本约 **14 元/月**（按 750 题估），远在 200 预算内。

**D. 误判错四根因分类**（→ 修订 §4、§5.1、§5.2）
1. **纯判分模型错**：提取全对仍判错 → 客观题**禁止让模型判分，改"提取 + 代码归一化比对"**（§4 新增"模型只提、代码才判"，§5.2 客观题路径重写）。
2. **提取错级联到判分**：坏题目被"合理"判错 → **提取质量前置闸门升为一等公民**（§4 新增，§5.1 强化：题目残缺/含 `〔?〕`/作答空 → 直接人工，不进判分链路）。
3. **`〔?〕` 占位机制工作正常**（两家在不确定时都能占位）→ 保留，下游按"占位即人工"路由。
4. **模型方差**（同输入两轮不同结论）→ 过程题判分**允许波动**，必要时多次采样一致性检查（§5.2）。

**E. 双页平铺照片是两家共同弱项**（页级识别扫尾：豆包 8/10、Qwen 4/10；物理 3-4/5-6 两页都失败）→ P3 页级导入前需增加"单页拍摄引导"或"整页自动裁切预处理"。

   - **初中数学** `blind_verified: true`（1407 题 A/B 双轮盲解、题库答案错 0；**唯一可当高可信冷启动**）；
   - **初中英语、初中物理** `blind_verified: false`（`verify` 与答案**同源**、无二遍盲解，英语章节归属大面积"册次待核"）→ 降级为**"参考冷启动 + 家长复核"**，UI 明示；
   - 高中题（数学/英语）同上 `blind_verified: false`。
4. **§14.4 数据形态再钉**：SQLite **不复制 topic 数据**、只在错题挂载时存 `external_id` 溯源；seed 与题库**以 JSON 文件形态随仓库分发**（1.5–4.7 MB 单文件、UTF-8 无 BOM），运行时按需读入内存索引，别塞进 SQLite。题目**内联 SVG 必过 HTML 净化**再渲染（防 XSS）。
5. **§14.5 化学、语文空 seed 补法收紧**：**不另找源、不自建细粒度题库**——直接复用同 JSON 契约（topics + dependencies 同款 schema），家长对课本目录录**章级粗粒度 40–80 点**（`mastery_criteria` 可精简、无题、`unaudited: true`），边只标明显的 hard 几条；细粒度交给 §5.3 既有的"错题驱动受控生长"。化学初三才开、语文主要走自评/讲解档，冷启动题库价值低。
6. **§14.6 教材 mappings 现实修正**：`docs/edition-mappings.md` 定义了 schema 但仓库**实际只有 6 条 "不得引用" 的占位示例**（topics 里 `mappings` 字段 0 条）。StudyDesk 教材包机制**可以照它的 schema 建**（`mappings/<版本id>.json` + `status: example|draft|reviewed`），但**沪教/苏教等实际数据要自己逐年级建，现成东西为零**。
7. **§14.7 engine.js 移植难度 = 低–中**：图算法约 200 行纯函数可直译 Python；真正工作量在 `judgeAnswer` 规范化——**已写入 §5.3 前置回溯诊断细则**。

## 16. v2.5 修订记录（2026-10-28，流程改向：批改外移 + 零模型 + 同类题考核）

> **本节取代 §3、§4、§5.1、§5.2 以及 AGENTS §4/§5/§6 中的相关旧条目；凡冲突处以本节为准。** 触发原因：Phase 0 手写识别准确率 0–0.5 是主瓶颈、整页切片回归（16 题被误切成 2 栏）、VLM 误配 OCR 返回空题——系统内自建视觉/判卷链路脆弱且成本高。核心洞察：**真实错题本来就来自"老师/家长已批改"的卷子**，"判卷"这一步既拿不到答案、又不该让模型判——那就**把它整个移出系统**，让系统退回到它唯一不可替代的职责：**可信地记、确定性地排、稳定地给孩子考**。

### A. 新闭环（外部管"对错与想通"，系统管"记·排·考"）

**外部（纸上，零系统算力、不需要答案库）**：无论练习还是考试卷，一律**在卷子上红笔批改 + 订正**，拿不准的题在系统外找豆包/家长做**引导 + 讲解**。卷面最终留下三样东西：**原题、划掉的错答、订正后的正答**。"批改/引导/解析"到此全部完成，系统不掺和。

**系统（wengu 确定性内核，五步）**：
1. **提取入库**：外部 agent 整页拍 → **认红笔批改痕迹挑出错题**（不再做题号锚点盲切片）→ 按版本化模板转录 `题干 / 错答 / 正答 / 错因建议 / 知识点建议`（看不清 `〔?〕` 占位）→ 输出 JSON 写入 wengu **监听目录** → wengu 后台**确定性校验 + 归一 + sha256 去重** → 落 `ingestion_drafts`（**导入全程不调模型**）→ **核对页人工确认才转正**。系统内**不保留任何 OCR/VLM 提取**，只留一个"**家长手填最小表单**"作离线后手。
2. **归类**：错因 AI 建议 + 知识点建议均来自 agent 模板；核对页确认转正（**AI 建议值 vs 确认值分离**照旧）。
3. **复习调度**：固定阶梯 × 掌握度自适应 × 抗挫败三规则，确定性重算、FSRS 留口（**不变**）。
4. **出同类题考核**：本轮纳入（原 Phase 3 提前）——见 §16.D。
5. **家长看板**：只读确定性统计（**不变**）。

### B. wengu 转为零模型（取代 §3、§4 prompt/成本护栏、AGENTS §4）

- wengu **不再调用任何云端模型**。`providers/{doubao,qwen_vl,tencent}`、`VisionProvider` 的 `extract_problem/grade/solve_explain` 路由、**成本护栏**（每日批量上限/内容哈希缓存）、`model_runs`、`llm_prompts/*.md` **全部退役**，仅保留 `providers/mock.py` 供测试。§3"至少两家供应商互备"护栏撤下。
- 唯一可能用到模型的"错因归类 / suggested_topic_id /（可选）家长周报叙述"**一律外移到 agent 模板/agent 定时任务**产出，以"文本或标签 + 来源=`ai`"入库，**绝不进判分/排期链路**。
- **§5"模型只提、代码才判"不删除、只收缩作用域**：真实题不再"提+判"（外部已判），该纪律**平移**到"系统自造同类题考核"——系统拿题库已知答案、`judgeAnswer` 代码归一化比对判分，仍禁止让模型判分。
- **prompt 版本化真源**从 `llm_prompts/*.md` **平移到 `docs/templates/*.md`**（frontmatter `id`+`version`、改语义必递增版本、agent skill 只引用不内嵌）；提取模板是它唯一值得版本化的后继。

### C. 外部导入字段契约与通道（取代 §5.1 兜底通道）

- `channel` 新值 `agent_transcribe_v1`（兼容旧 `doubao_json`）。ingestion 草稿字段**新增 `standard_answer`（必填，取卷面订正的正答）**、`verify`（可选）、`error_cause_suggestion`、`suggested_topic_id`；沿用 `subject / problem_text / student_answer / source_ref / captured_at`。
- 仍是"导入即不可信输入"：校验大小/题数/字段长度、**提示注入防御**、`〔?〕` 占位不猜、坏项跳过并逐条报告。**提取质量前置闸门**保留——含 `〔?〕`/残缺/`standard_answer` 缺失 → 核对页强制人工处理、不得自动转正。
- 落地形态：**Skill/定时任务只写 JSON 到监听目录**（解耦 wengu 是否在线），**只到草稿、绝不自动转正**；转正走核对页人闸（回显总闸守住）。**施工顺序：先建新入口 + 监听目录导入引擎跑通闭环，再删旧视觉栈**（防中途断档）。

### D. 复习闭环新增"出同类题考核"（取代 §5.3/§5.4/§5.11 相关；Phase 3 的检索组卷提前）

- **来源只检索 seed 题库**（`cn-math-taxonomy` 初中 2803 题），**同 `topic_id` + mulberry32 固定种子可重放**；**绝不让 LLM 凭空编题**（§2/§12 红线不动）。前置工程：把 `questions.json` **载入内存索引**（不进 SQLite，守 §14 数据形态）+ 题库支持按知识点 `topic_id` 检索（现 `problem_bank` 无 topic 列）。
- **错题 ↔ 知识点是多对多 + 一个 `primary_topic_id`**：掌握度/排期仍**取所有已确认 concept 中最小 mastery**（不变）；**同类题只按 `primary_topic_id` 检索、每次出 1 题**（避免一道多知识点题一次推 N 题压垮孩子）。**核对页必须人工确认 topicId 才排考核**；未确认 → 只走原题重做、不考核。
- **到期行为 = 考核优先、重做兜底**：到点能按主考点检索到同类题 → 推**考核**（系统判）；检索不到 → 退回**原题重做（自评）** + 标"该知识点题库缺口"。覆盖现状：数学 1407 / 英语 1028 / 物理 368 / **语文 0 / 化学 0** → 后两科基本全走重做 + 缺口标记，靠教材包机制补。
- **触发两者都要**：复习到点自动推 + 家长手动组卷。
- **判分**：客观/短答题在**系统内作答、代码归一化比对** bank `answer`（`answer+accept+unordered+judgeAnswer`，运行时不 eval）；bank `verify` 在**入库时**过 AST 白名单沙箱核验。数学**解答大题无法键入** → 降级"纸上做 → 拍已批改 → 自评"。
- **结果去向**：闭环考核结果**计入该知识点掌握度（打 `source=system_quiz` 标签）、可整表清空、但不新建错题本条目**；**主动加练的"变式"仍纯走 `practice_records`、不影响掌握度**。唯一写入路径**只由"卷面已确认的真实错题"驱动**不动摇。
- **掌握度双来源（MVP）**：`student_self`（原题重做自评）与 `system_quiz`（系统判考核）**各计 1 次、仅打来源标签、可整体重算**；暂不加权（样本 < 3 不下结论，跑真数据再定）。
- **§5.3"入本 = 批改判错的自动副产品"改写**为"**入本 = 核对页确认的外部转录错题**"（不再有系统内自动批改副产品路径）。**三段式讲解（§5.5）对真实错题移外部**；系统内讲解仅在"自造考核题卡壳"时可选复用，非主链、可后置。
